- Everything else (`benchmark_data/`, `data/`, `emnist/`, `mnist/`, `narrative_figures/`, `cpecog_extracted/`, `photo_splits.json`) is data and unchanged.

- `sudoku_core.py` — OpenCV pipeline: grid detection/warping, cell extraction, solver. `full_pipeline()` is the top-level entry. `extract_cells()` uses **FRACTIONAL boundaries** (i*h/9 rounded) — `size // 9` truncates (600 -> 66 px), misaligning every later row/column and discarding the last 6 px of the warp; this was the biggest single pipeline defect found (true-5 accuracy 96.5% -> 99.1% after the fix, wrong cells 33 -> 30 on the HF 24-sample with the SAME smoke model). `line_grid_quad()` gates line spacing against the SOURCE min dimension (the grid spans the source image), not the requested output `size` — the old size-based bounds rejected valid 300 px and 1200 px images. The solver is one shared engine, `_search(grid, domains, branch_order, max_nodes, stats, accept_fn)`: 10-bit per-cell candidate domains (bit 0 = "release" marker), 9-bit row/col/box used-masks, **constraint propagation at every node** (naked singles + hidden singles), MRV branching only when no cell is forced, trail/undo, and a total node budget that aborts the whole search (stats dict: `nodes`, `propagated`, `limit_hit`, `ok`). When propagation dead-ends the search UNDOES the partial fills and branches on a releasable order cell — first one whose candidate list STARTS with 0 (release = its first action when the CNN guessed empty), then (NEW) any order cell whose list merely CONTAINS 0 (suspects keep 0 LAST so a real correction is preferred over deleting a given; without the fallback the search looped on the contradictory restricted domain and burned its node budget). Public wrappers: `solve_sudoku(grid, max_nodes=100_000, stats=None)` (full-domains plain solver, returns `(grid, ok)`, rejects duplicate givens upfront) and `solve_with_correction(grid, candidates, order, max_nodes=200_000, change_budget=4, stats=None, budget_ref=None)` — ONE integrated confidence-aware search fed by `candidates_from_probs(probs, max_alts=3, conf_thresh=0.9, order_cap=12)` (per-cell softmax -> `{idx: [best-first alternatives]}` + the 12 least-confident cells): non-order cells are fixed to the recognized values (duplicate digits among them rejected upfront), order cells branch over their CNN candidate lists inside the same search (a guess duplicating a fixed digit is rejected on the spot — high-confidence cells act as hard constraints), class 0 = release a cell so the solver fills it freely, and a completed grid is accepted only if at most `change_budget` recognized digits differ (else the search continues; the cap keeps correction from wandering into a valid sudoku unrelated to the photo). `budget_ref` = the FIRST-PASS recognized grid for the budget: `solve_with_resensing` UPDATES the working puzzle to each re-sensed cell's new argmax between rounds (a changed opinion now actually reaches the search — it used to be stranded) while the budget keeps counting edits against the original recognition. `solve_with_resensing(..., preprocess_kwargs=None)` forwards benchmark A/B overrides (margin_frac, ...) to `preprocess_variants`, which now also forwards them to `_finish_preprocess` (sweeps used to cover the first pass but not the re-sense path).
- `run_sudoku.py` — CLI: `python run_sudoku.py image.jpg [--model models/digit_cnn.pth] [--size 600] [--show | --save out.png]`. Console default (prints recognized grid + solved grid); optional 2x2 matplotlib figure (original+quad, warped, recognized, solution). Uses `predict_cells_probs` + `solve_with_resensing` (no ink-ratio gate). Reads images via a Pillow fallback (cv2 cannot decode webp). Exits NONZERO on unsolved puzzles / unreadable images / incompatible weights (a clean error, not a traceback). Prints solver DIAGNOSTICS: a plain-grid probe (`solve_sudoku`, 10k node budget) with node counts + a warning naming duplicate-digit suspects / least-confident cells when the recognized grid does not solve cleanly (a node explosion = the CNN corrupted the puzzle, not a slow solver), then the correction search's node count.
- `live_solver.py` — real-time Tkinter GUI app: `python live_solver.py [--model models/digit_cnn.pth] [--camera 0] [--size 600] [--smoke [image]]`. THREE background threads: `ModelThread` loads weights + temperature sidecar off the UI thread; `CameraThread` captures (DirectShow preferred on Windows — MSMF leaks frame buffers with some webcam drivers); `SolverThread` runs detection → warp → CNN → `solve_with_resensing` with a busy-gate (at most ONE frame in flight/pending per pass) + a 150 ms throttle, so the queue can never pile up while a slow pass runs. UI: left preview shows the live frame with the detected quad and overlay digits — WHITE = recognized givens, YELLOW = solver-filled cells, drawn with a dark outline at true bilinear cell centers via the same `order_points` as the warp; right panel shows Recognized + Solution 9x9s in 3x3 boxes — labels are appended ROW-MAJOR so label i ↔ `grid.flat[i]` (the original block-major append order stuffed each grid row chunked into one 3x3 box, misplacing 54/81 cells); status block (detection method, solve status with node counts, model path); toolbar with camera picker, Start/Pause/Snapshot (pauses, drains, re-solves the frozen frame), Upload (Pillow fallback decodes webp). Detection = the same contour → `line_grid_quad` chain as the benchmark (no hough). `--smoke [img]` solves one image and auto-exits 0/1 — a CI-able health check printing `SMOKE: ...`. Gotchas: the file is UNTRACKED in git; the video label's requested size is pinned (width/height) so each displayed frame can't grow the Tk window (~+40 px / 2 s measured).
- `digit_cnn.py` — PyTorch `DigitCNN` (48x48 input, **double-convolution stages 32->64->128, 2x Conv3x3-BN-ReLU per stage + MaxPool2**, then a **GAP head**: `AdaptiveAvgPool2d(1,1) -> Flatten -> Dropout(0.3) -> Linear(128, 10)`. GAP replaced the old size-locked `Linear(4608, 10)` flatten head — 46k -> 1.3k head params, no positional bias, and the 48x48 input lock is gone), `fit_temperature(model, X_val, y_val)` (temperature scaling — ONE scalar T minimizing softmax NLL on the val split; fit on the PHOTO val split when present, since synthetic val calibrates the wrong distribution; T flattens overconfident softmaxes so wrong cells stop clearing `conf_thresh=0.9` and the correction search actually revisits them; argmax unchanged, confidences only) + `save_temperature`/`load_temperature` (sidecar `<weights>.temperature.json`, auto-loaded by `run_sudoku.py` and the benchmark; `predict_cells`/`predict_cells_probs`/`classify_preprocessed` accept `temperature=`), `make_empty_cells()` (synthetic class-0 empty cells calibrated to the measured post-preprocessing appearance of real photo empties under the CURRENT pipeline: ~97% pure black, ~3% with surviving thin line fragments/blobs at 5-15% ink; fragments are drawn at full intensity then pushed through `_letterbox_fragment` — the SAME tight-crop/12% pad/aspect-preserving-resize geometry `_finish_preprocess` applies to real survivors, so generated empties match the post-cleanup look instead of staying at native scale), `make_synthetic_digits()` (curated COMMON PRINT fonts only - DejaVu/Arial/Times/Courier/Verdana/Georgia/Tahoma/Corbel/Segoe UI/Liberation/Free*, no decorative fonts - rendered dark-on-light, CONSERVATIVE augmentation on the RAW cell BEFORE preprocessing: zoom 0.8-1.0 / shift ±2 px (via `translate()` — cv2 warpAffine with black border, NOT np.roll which wraps pixels around) / rotation ±8° / occasional erode-dilate print-weight / brightness-contrast lighting / weak noise N(0,2-6) / occasional light blur — then through the same `preprocess_cell`), `make_emnist_digits(n_per_class=None, root="emnist", return_test=False)` (EMNIST `split='digits'` — 252k handwritten digits 1-9 after dropping digit 0 (class 0 = empty), 28->56 upscale then `preprocess_cell`, per-class cap for CPU runs, full packed arrays **cached to `emnist/emnist_packed.npz`** (~2.3 GB) so repeat runs skip the ~5-15 min preprocess loop; the cache is now VERSIONED (`preprocess_version`) — an old-format cache is regenerated, never silently reused — and the OFFICIAL TEST SPLIT IS KEPT SEPARATE (keys X_tr/y_tr/X_te/y_te): training never sees official test pixels, and `return_test=True` yields `(X, y, Xt, yt)`), `train_digit_model()` (AdamW lr 3e-4 + weight_decay 1e-4 + ReduceLROnPlateau; saves the BEST-epoch weights, not the last), `load_digit_model()` (validates the state-dict KEY SET against the current double-conv architecture — legacy single-conv weights fail with an explicit message instead of loading garbage; notebook-style `{'model_state_dict': ...}` checkpoints are unwrapped), `predict_cells()` (returns preds+confs), `predict_cells_probs()` (returns full (81,10) softmax). All three inference helpers call `model.eval()` themselves, so a caller can't leak training-mode dropout/BN into inference. **Preprocessing (Phase 1 redesign, v5)**: `preprocess_cell(cell, target=48, margin_frac=0.10, min_area_frac=0.005, empty_frac=0.01, corner_span=0.4, grid_thin=2.5, ...)` is the CURRENT pipeline — adaptive threshold (block 15, constant 7, inverted — each pixel's threshold is the local 15x15 Gaussian-window mean minus 7, so the threshold follows shading across the cell instead of using one global value; a global Otsu pass runs ONLY when adaptive is clearly degenerate — a joint statistical gate: foreground ink fraction `(th>0).mean() < 0.5%` AND intensity spread `blur.std() > 18`; once the gate fires, Otsu's output REPLACES adaptive's unconditionally — the two thresholds are never compared on ink fraction, because comparing `otsu_ink > adaptive_ink` (the LEGACY behavior) let a degenerate global result silently clobber a working adaptive one), 10% margin strip, then shape-based cleanup on the stripped region: line fragments removed (edge-to-edge: thin <6 px area/length AND elongated aspect >4; one-border: thin <2.5 px AND elongated AND spanning ≥70%), L-shaped corner remnants (<6% area, ≥40% spans both dims), tiny components dropped (<0.5% of the FULL cell — fractions always use the full cell), conditional split-stroke merge via a THIN BRIDGE (1-2 px cv2.line through the gap — NOT a rect fill; gap ≤5 px, aligned, each piece ≥0.5%, union digit-like), ALL surviving components kept (no largest-component-only step: digits never truncated, digit+specks go to the CNN whole), conservative EMPTY as a SEPARATE rule (largest surviving <1% -> all-black; thin strokes never rejected), letterboxed resize. Sweeps (same low-epoch model) confirmed the defaults: margin 0.04/0.08/0.12 -> definite 94.1/96.1/96.2%, empty 0.005 -> 98.4%, corner_span 0.3 = 0.4 — margin 0.10 + empty 0.01 + corner_span 0.4 is the optimum. NOTE: an Otsu-retry-on-lost-digit idea was tested and REVERTED (measured: it fixed 0 of the 7->0 cells and introduced a false digit on an empty cell — the 7s are lost at threshold/margin level, not recoverable by a second global threshold). **`preprocess_cell_legacy()` is the FROZEN pre-study pipeline, kept for A/B testing and regression** (do not modify); `preprocess_cell_stats(cell, target=48, **kwargs)` returns the processed cell + per-cell diagnostics (threshold path, ink fractions, removed_tiny/grid/corner counts, merge flag, stage images) for the benchmark's `--cell-dump`/`--cell-montage`. `predict_cells`/`predict_cells_probs` accept `**preprocess_kwargs` (forwarded to `preprocess_cell` for sweep runs).

  - **HF (primary)**: `python benchmark.py --hf-sample 24` downloads ONLY a seeded
    sample of images (metadata.jsonl + N images via urllib - fast, no datasets lib);
    `--hf-dir data/<split>` works without the datasets lib; `--hf` uses the datasets
    lib for full splits. **Sealed-split mode**: `python benchmark.py --split-file
    photo_splits.json --split-name test --model <w>.pth` evaluates the exact
    partition's puzzle names (photo_data.py) — this is the OFFICIAL number for
    photo-trained models. `Lexski/sudoku-image-recognition` = 1400 images, explicit
    train/val/test; ground truth = (9,9,10) cell flags (flag 0 = solved, flags 1-9 =
    digits; candidate-only cells are non-definite and skipped) + 4 keypoints in
    TL,BL,BR,TR order (reordered to TL,TR,BR,BL before warping). Headline metric =
    solved-cell DIGIT accuracy; also empty/definite-cell accuracy, exact grids, solve
    rate, per-digit, per-puzzle `*`-marked grids + figure.
  - **wichtounet folder**: `python benchmark.py --data-dir <clone>`. Dataset VERSION
    is detected from the first csv-referenced `.dat` (V2 givens vs `mixed/` complete
    81-digit grids) and printed — the two are never mixed; outlines_sorted.csv
    references `images/` (V2) only.
  - Both report grid detection method breakdown (contour/lines/keypoints + failed)
    and run TWO separately-labeled modes (`--mode recognition|e2e|both`, default
    `both`): RECOGNITION/SOLVER warps the ground-truth corners (isolates CNN +
    solver from detection), END-TO-END ignores corners and auto-detects (contour ->
    lines, NO center-crop fallback — misses are counted honestly in a
    "grid detection" rate and excluded from recognition metrics).
    The labeled data trains the CNN under the SEALED 70/15/15 split
    (photo_data.py) — only the TEST partition is off-limits for training;
    `--split-file --split-name test` benchmarks exactly those sealed photos.
    The benchmark also loads `<model>.temperature.json` automatically.
    Also prints a `solver nodes` line (mean/max correction-search node counts +
    node-limit hits — a node explosion signals CNN-corrupted puzzles), a
    wrong-cell CONFIDENCE report (Case A conf<0.5 vs Case B conf>0.9 — Case B
    dominance signals a preprocessing/domain mismatch), and 9x9 position
    matrices for BOTH accuracy and sample count (a 100% on a 3-cell position
    is not overinterpreted). EXTRA semantics (post-fix): "exact grids" is
    labeled definite-cells-only; there are now also `no-duplicate grids` (full
    81-cell recognized grid without unit duplicates), `gt-preserving` (valid
    solution that keeps EVERY ground-truth definite clue — a valid-but-different
    sudoku is NOT counted as solved), a `candidate-only cells read as digits`
    line (HF candidate-only cells are ignored by the accuracy metrics but reach
    the solver as possible false clues — 478/577 on the HF 24-sample), and an
    ORACLE diagnostic that re-solves failed puzzles with candidate-only cells
    emptied (diagnostic only, clearly labeled). `--device cuda` now ERRORS if
    CUDA is unavailable (it used to silently run on CPU and distort node stats).
    Diagnostics: `--cell-dump cells.csv` writes
    per-definite-cell rows (photo, r, c, gt, pred, conf, threshold, fg_frac,
    post_ink_frac (surviving ink after cleanup), comps, largest_frac,
    removed_tiny/grid/corner, merged) and
    `--cell-montage base.png` saves per-error-group preprocessing-stage
    montages (empty->digit, 1->7, 7->1, 8 reference, other).
    Preprocessing A/B sweeps: `--pre-margin`, `--pre-empty`, `--pre-corner-span`
    override the preprocess defaults for the whole run (forwarded to every
    `preprocess_cell`/`preprocess_cell_stats` call AND through re-sensing —
    same model, only the preprocessing changes). `benchmark.run(data_dir, ...)`
    is a folder-mode wrapper used by `train_local.py --benchmark-data-dir`
    (the old `benchmark.run` was missing and crashed post-training runs).
- `train_local.py` — local training mirroring the notebook (empty cells + curated print-font synthetic + optional MNIST/EMNIST via torchvision, **plus REAL PHOTO cells**: `--include-photo` pulls the train+val partitions of the sealed Lexski split via `photo_data.py`; the photo TEST partition is never loaded), saves best-epoch weights, fits + saves the temperature sidecar (`<out>.temperature.json`), optionally runs `benchmark.py` after: `python train_local.py --epochs 40 --empty-per-class 15000 --include-synth --include-mnist --include-emnist --include-photo --warm-start <synthetic.pth> --lr 1e-4 --benchmark-data-dir <clone>`. **Adaptive**: `--device auto|cpu|cuda` (auto picks cuda when available), `--batch-size` (default 256 — the old 1024 dropped for gradient diversity; photo cells join as their own "photo" source with equal weight in the balanced sampler; `--emnist-per-class 0` = uncapped, auto-capped to 10000 on CPU; `--mnist-per-class` caps MNIST per class — both caps are for smoke runs). Model = double-conv DigitCNN with GAP head, optimizer = AdamW lr 3e-4 + wd 1e-4 + ReduceLROnPlateau, conservative augmentation (rotation ±8°, shift ±2 px, weak noise, occasional blur, brightness/contrast). `--warm-start <path>` initializes from a pretrained checkpoint (fine-tune the synthetic model on photos with lr 1e-4 — preserves the clean digit morphology instead of relearning it from ~50k photos). POST-FIX training infra: the OFFICIAL MNIST/EMNIST TEST SETS ARE KEPT SEPARATE (the old code concatenated them into the pool and split randomly — the reported test accuracy is now a genuine official-test score, e.g. 95.3% on the 3-epoch infra smoke); augmentation is applied LAZILY per epoch via `AugmentedDataset` + a source-balanced `WeightedRandomSampler` (EMNIST's ~69% share no longer dominates the gradient; the old eager `np.stack` copy is gone); per-epoch checkpoints (`--ckpt`, `--resume`) survive crashes; **early stopping** (`--early-stop-patience 5`, `--min-epochs 12` — notebook parity); `--dry-run` prints sizes + RAM estimate before training. The final test eval is BATCHED (one 21k-sample forward pass OOMs the 8 GB GPU — activations ~6 GiB on the first conv). `--out` defaults to `digit_cnn.pth` (overwrites!); use a custom path for verification runs. ## Known bugs / gotchas
- `preprocess_cell` exists in BOTH modules with different return shapes: `digit_cnn.py` returns `(48,48,1)` float32 (required by `predict_cells`); `sudoku_core.py` returns `(48,48)`. Don't mix them.
- Cell order is row-major (81 cells, index `r*9+c`); `sudoku_from_cells` reshapes to 9x9.
- **Class 0 = empty cell** everywhere (not the digit 0): `sudoku_core.sudoku_from_cells` has no ink-ratio gate, the CNN decides; the old `cell_has_digit` gate was removed. Any `digit_cnn.pth` trained with the old semantics will misbehave — retrain required. `load_digit_model()` now REJECTS incompatible weights with an explicit error.
- Digits are trained on *synthetic* rendered fonts, MNIST/EMNIST and (optionally) REAL PHOTO cells — `make_synthetic_digits()` scans `C:\Windows\Fonts` on Windows, and every synthetic/MNIST/EMNIST sample is passed through the same lenient `preprocess_cell` as photo cells (inverted dark-on-light). Renders/save in `train_digit_model()` overwrite `digit_cnn.pth` by default (BEST epoch). Photo data is trained on ONLY under the sealed split (`photo_splits.json`): the TEST partition is off-limits; `benchmark.py --split-file --split-name test` is the official evaluation.
- Model weights were saved on this machine; `torch.load(path, map_location=device)` is used, so CPU-only loading works.
- The optional Kaggle-upload cell (3b) only prompts when `data_mode="kaggle"` and `~/.kaggle/kaggle.json` is absent; default `data_mode="auto"` (GitHub clone) keeps `Runtime > Run all` credential-free and unblocked. Cell 1 must not pip-install torch/torchvision/opencv (would replace Colab's GPU wheels).
